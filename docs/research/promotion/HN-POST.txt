Author here. I wrote this after losing an afternoon to the first item on the
list — a rule file sitting in .cursor/rules doing absolutely nothing, because
Cursor only reads .mdc there and ignores .md silently.

Every path in the post is checked against the vendor's own documentation and
linked, because searching for this returns a remarkable amount of
AI-generated filler that contradicts itself. Where I could not confirm
something at the source I say so rather than guessing.

The Gemini detail is the one I find most interesting structurally: because its
commands are TOML with a "prompt" key rather than Markdown, the container
format differs and not just the field names. That rules out solving this with
symlinks alone, which is annoying, because symlinks otherwise solve most of it
cleanly.

Disclosure: I did end up building a tool for this and it is linked at the end
of the post. rulesync and ruler are both more mature and support far more
tools; I mention them in the piece for that reason. The post stands on its own
whether or not anyone touches mine.

Happy to be corrected on any of the paths — these formats move quickly.


================================================================
IF SOMEONE ASKS "why not just use rulesync?"
================================================================

rulesync is more mature and supports 40+ tools. If breadth is what you need,
use it. Mine does two things differently: it symlinks instead of generating
copies, so editing any mirror edits the source rather than being overwritten
on the next run, and it syncs automatically via hooks or a watcher rather than
when you remember. The tradeoff is deliberate: six tools verified against
vendor docs instead of forty.
